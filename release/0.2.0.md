# Scvm Rack — v0.2.0

**Release date:** 2026-05-29
**Type:** Minor — first production-candidate release

> The world is ending, but we keep shipping.

This is the first tracked release of Scvm Rack, the interactive MÖRK BORG
character sheet. It covers the full backend API and React frontend, with this
cycle's focus on a server-side feedback/error-reporting pipeline, a centralized
API error model, and a consolidated test suite ahead of production.

---

## Highlights

- **Server-side feedback & error reporting.** A new `POST /api/feedback` endpoint
  forwards user feedback and unexpected errors to GlitchTip from the server. The
  frontend auto-surfaces a feedback dialog on unexpected API errors (enriched with
  status, API code, and request id) and offers a manual feedback form.
- **Centralized, structured API errors.** Every error now returns a consistent
  payload — `{ error, message, code, statusCode, requestId, details? }` — with
  Fastify validation and Prisma/PostgreSQL codes mapped to stable API codes. 5xx
  responses never leak internals and are reported to Sentry.
- **Hardened test suite.** Backend unit (`node:test`), dockerized integration, and
  Playwright E2E (authenticated character management, print, kill/replace,
  custom-item header, error paths), plus React unit and browser tests.

---

## Backend

- Characters: generate / list / count / fetch (localized) / update / delete, all
  ownership-enforced under `/api/characters`
- Equipment: locale-aware fuzzy search and full-item fetch under `/api/equipment`
- Feedback: `POST /api/feedback` — rate-limited (20/min), CSRF-protected,
  schema-validated; no-ops gracefully without a Sentry DSN
- Centralized error pipeline (`errors.ts` + `error-handler` plugin) with a custom
  structured 404 handler
- Input sanitization for character updates (string escaping, jsonb scrubbing,
  numeric bounds clamping)

See [`../changelog/backend.md`](../changelog/backend.md) for the full surface.

## Frontend

- Character sheet with optimistic updates, debounced autosave, and retry-on-failure
- Inventory: equipped bar, on-hand/storage, ammo tracking, consumables, pets,
  custom items, computed + custom modifiers, ability/power uses, Kill & Replace
- Feedback: automatic error dialog + manual feedback form wired to `/api/feedback`
- Auth: Logto sign-in, anonymous guest sessions, character claim, session-expiry
  handling
- Pages: Landing, Characters list, Character, Print, FAQ, Release notes, 404
- Fully localized (English / Polish); consent-gated analytics; per-page SEO

See [`../changelog/frontend.md`](../changelog/frontend.md) for the full surface.

## Security

- Session cookies `HttpOnly` / `Secure` / `SameSite=Lax` / `__Secure-` prefixed
- HSTS, HMAC double-submit CSRF on state-changing routes, per-endpoint rate limits
- Prisma-parameterized SQL; Swagger disabled in production; non-root container
- Pentested with Shannon AI (2026-03-23); findings remediated or accepted

## Fixes & maintenance

- **Fixed** a missing `getCsrfToken` export in `@/api` that the feedback reporter
  imported — the frontend production build (`npm run build`) was failing typecheck
  and feedback submission would have thrown at runtime.
- **Fixed** broken backend unit test (`feedback.test.ts`) that imported `vitest`
  into the `node:test` runner with a wrong module path — `npm test` / CI `test:all`
  was red and is now green.
- **Fixed & stabilized the browser test suite** (previously "flaky"): repaired a
  wrong i18n import path and several incomplete `vi.mock` factories that caused
  cascading module-import failures. The default `test:browser` run now uses a single
  engine (chromium) with a small retry, and `test:browser:all` exercises every
  engine in its own process. The suite is green and deterministic across runs.
- **Migrated** the frontend ESLint setup from a legacy `.eslintrc.cjs` (which never
  executed under ESLint 9) to a flat `eslint.config.js`; `npm run lint` works again.
- **Renamed** the `useAmmo` editor action to `consumeAmmo` to resolve a
  rules-of-hooks false positive (it is a callback, not a hook).
- **Refreshed** the in-app release notes page (`/release`) to show real history
  instead of placeholder versions, in sync with this `release/` folder.
- **Hardened the frontend edge** — added CSP / HSTS / `X-Frame-Options` /
  `nosniff` / `Referrer-Policy` to the Caddy frontend routes. Previously the app
  document and static assets shipped with no security headers (only the API, via
  helmet, was covered). See `Caddyfile.example`.
- **Localized `<html lang>`** — it now follows the active language (`en`/`pl`) for
  correct screen-reader pronunciation and SEO.
- **Unified the public brand to "Scvm Rack"** across the HTML shell, web manifest,
  and design docs (the SPA already used it at runtime via the SEO component).
- **Set the OpenAPI/Swagger doc version to 0.2.0.**
- **Enabled Google Analytics in production builds.** The GA4 measurement ID is now
  threaded through the frontend Docker `ARG`/`ENV` and `compose.prod` build args; it
  was previously absent from the prod bundle, leaving GA dormant. Analytics stays
  consent-gated (via the privacy notice) and IP-anonymized.

## Known issues

- Cross-browser runs (`npm run test:browser:all`, Firefox/WebKit) may still show
  occasional engine-specific timing flakiness; chromium is the canonical CI signal.

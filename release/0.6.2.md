# 0.6.2 - Steadier first visits and fairer rate limits

## First visit on phones and in-app browsers

Some first-time visitors, mostly arriving on mobile and inside in-app browsers, were seeing a sign-in error before they could create a scvm.

- **Guest sign-in recovers on its own** — if the browser already holds a guest session, or a connection blip interrupts sign-in, the app now picks the session up or retries instead of showing an error.
- **No stale sessions** — session and security-token responses are now marked as never-cache, so a browser or proxy can't reuse an out-of-date "not signed in" answer.

## Fairer rate limits

- **Per visitor, not per server** — the request limits were being shared by every visitor at once, so a busy moment could lock brand-new visitors out with "too many requests". They are now counted per visitor.
- **More headroom** — the general limit is now 300 requests a minute per visitor (was 100).

## Also in this release

- **Oversized item ids** — asking for an impossibly large equipment id now returns a proper "bad request" instead of a server error.
- **Quieter monitoring** — cosmetic browser page-transition glitches and search-indexer bots are no longer reported, and a guest sign-in that recovered on its own is logged as a low-priority warning so we can measure how often it happens.

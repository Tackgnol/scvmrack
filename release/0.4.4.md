# Scvm Rack — v0.4.4

**Release date:** 2026-06-25
**Type:** Patch — backend hardening

Internal plumbing pass: structured error logging, SSE connection cleanup, and a complete architectural cleanup of the backend data layer so catalog reads go through repositories instead of calling the database from inside library code.

---

## Under the hood

- **Structured error logging.** Unexpected errors in the service layer now capture the full stack trace in Pino's log output. The `unexpected()` helper previously passed the raw error as a positional argument; it now uses `{ err: error }` so Pino's error serializer records the stack.
- **SSE half-open connection fix.** The party live-update stream (`GET /api/parties/:id/stream`) now explicitly closes the raw socket in its cleanup path. Previously, if a write error triggered cleanup before the client disconnected, the server-side socket was left half-open.
- **Repository layering restored.** The backend's documented invariant — repositories are the only layer allowed to call Prisma — was violated by three library files (`inventory.ts`, `get-character-full.ts`, `item-search-service.ts`) that called Prisma directly. A new `catalog-repository.ts` was introduced as the single seam for catalog reads (weapons, armors, equipment, pets, classes, translations, class ability modifiers). All three library files now call the repository instead of the database directly.

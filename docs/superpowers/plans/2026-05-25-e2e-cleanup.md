## Task 5: Fix `/csrf-token` path in `fixtures.ts`

This is the one-line bug that prevents every authed worker from completing fixture setup.

- [ ] **Step 1: Apply the edit**

Open `backend/tests/e2e/fixtures.ts`. Find line 62 (inside the `getCsrfToken` function):

Replace:
```ts
  const response = await fetch(`${apiBaseURL}/csrf-token`, {
```

With:
```ts
  const response = await fetch(`${apiBaseURL}/api/csrf-token`, {
```

- [ ] **Step 2: Verify other API paths in this file are already correct**

```bash
grep -nE "apiBaseURL\\}/" backend/tests/e2e/fixtures.ts
```

Expected output:
```
62:  const response = await fetch(`${apiBaseURL}/api/csrf-token`, {
82:  const response = await fetch(`${apiBaseURL}${path}`, {
```

Line 82 takes the path as a parameter (used for `/test/users` and `/test/characters`). Those paths are correct as-is — they live outside the `/api` prefix because the test routes are mounted via `ENABLE_TEST_ROUTES`, not through the auto-loader. (Verifying that contract is P1a.5's job, not this task's.)

- [ ] **Step 3: Commit**

```bash
git add backend/tests/e2e/fixtures.ts
git commit -m "[FIX] (e2e): call /api/csrf-token in fixtures

backend/src/app.ts mounts all routes under the /api prefix, so
the CSRF endpoint lives at /api/csrf-token. Every authed
Playwright worker called the unprefixed /csrf-token and errored
at 'Failed to get CSRF token: 404' on fixture setup. Same class
of bug as the /api/health healthcheck path fixed in P0."
```

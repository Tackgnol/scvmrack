# Canary release fixes — 26 October 2026

Branch: `codex/canary-release-fixes`, based on `dev`. Scope: RPG-337, RPG-338, RPG-339 and RPG-340 (the five response-contract gaps from the 479-case canary CATS run). The contrast/footer work remains separate in PR #64.

## Behavior and boundaries

- **RPG-337:** shared-auth 2.1.0 stops treating `Window.closed` as cancellation. The initiating extension offers explicit cancellation using an AbortSignal until redemption begins; cancellation interrupts held registration/polling requests and delays, preserves the original error even if the host rejects window closure, and cancels the registered proof. Once redemption starts, Cancel disappears and caller aborts do not interrupt receiving-identity verification; the deadline still applies. Code approval, expiry, recipient secrets, identity verification, quarantine and one-use redemption remain enforced. The tested 2.1.0 archive is now published; its companion source PR still needs merge.
- **RPG-338:** the recovery banner, tabs and panels share one vertical GM shell. Composed browser tests exercise real pointer clicks, retry, visible comparison code, cancellation and both tabs at 420px in English and Polish. Pointer hit-tests cover the initial and failure states plus Cancel and both GM tabs while the code-expanded alert is open.
- **RPG-339:** monitoring starts preparing its own CSRF protection when enabled. The transport preserves SDK keepalive options and refreshes once after a 403. Initialization failures are caught; active reports can retry preparation. A pending or failed preparation may still require a lookup during departure; eager preparation is a mitigation, not a delivery guarantee. Public monitoring does not bootstrap an anonymous account or bypass CSRF.
- **RPG-340 / CATS contracts:** add class-list/detail validation responses, a complete catalog-row union, health bodies and room binding bodies. Reuse participation binding definitions so nullable connection/player fields and token generations remain consistent. Generated client changes are limited to these five paths. Review caught an equipment hpMod declared as a string despite Prisma's nullable integer; the corrected contract and real database fixture preserve numeric values without a serialization 500.

The 18 native browser protocol checks cover Chromium, Firefox and WebKit using real shared-auth HTTP, a memory auth adapter, the installed Sentry SDK, the protected tunnel, and local provider/GlitchTip fixtures. The isolated popup actually reports a closed handle while its page stays interactive; approval follows several pending polls. Aborts after real redemption and confirmation responses still finish with the approved identity and one ownership transfer. See [protocol suite](../../backend/tests/protocol/README.md). Real PostgreSQL integration tests separately cover ownership transfer and binding contracts.

Review caught and corrected a missing Cancel control while registration is still pending. The composed GM test now cancels both registration and code waiting before a successful retry, in both languages.
